# Reviewer向けガイド（日本語）

このガイドは開始前の説明用候補です。**PILOT HUMAN REVIEW NOT STARTED / MAIN HUMAN REVIEW NOT STARTED / HUMAN LABELS = 0 / NOT FINAL-FROZEN**。詳しい基準は[Codebook](CODEBOOK.md)、相談後の処理は[Adjudication Rules](ADJUDICATION-RULES.md)を参照してください。

## Reviewer候補について

Reviewerには成人または大学生相当以上で、日本語のこのガイドとCodebookを理解し、他Reviewerと相談せず初回判定を行い、pilot calibrationを完了できることが求められます。AI/LLMやNLPの専門知識は必要ありません。保存された観測可能な資料だけを使ってCodebookに沿って判断してください。Pilotで判定が難しいことが分かった場合、その人をMain Reviewerには採用しません。

この研究では査読上不要な疑義を避けるため、家族をMain Reviewer候補から除外します。これは今回の研究上の選択で、家族をReviewerとすることへの一般的・方法論的な禁止ではありません。実際の関係性は担当者へ申告してください。

## 何を判定するのか

保存された資料を見て、「回答に必要な事実が、その段階の文章に正しく残っているか」「届いた証拠で最終回答を支持できるか」を判定します。原文、Workerに実際に渡った入力、Workerの公開文章、公開Artifact、Synthesizerに実際に渡った入力、最終出力を、指定された順に見ます。

AIが頭の中で何を考えたか、理解したか、証拠を使ったかは推測しません。引用番号が合っているだけで、文章の意味まで正しいとはしません。正答しただけで証拠を使ったとも判定しません。

## 原文と日本語訳の読み方

日本語訳を主に読んで構いません。2名には同じ、事前に版とhashを固定した訳を提示します。**意味の基準となる正式な記録は英語原文**です。必要なら原文も確認してください。

訳が曖昧、原文と違う、判定に影響しそうな場合は、箇所と理由をtranslation issue／ambiguityとして残してください。原文で判断できても訳の問題は記録します。訳の問題をAI側の誤りと決めつけず、自分で訳を書き換えないでください。その場のAI翻訳も使いません。

最初のR1ではquestionとraw evidenceだけを見ます。Gold、Worker出力、最終回答など、まだ開示されていない資料を探したり、それで曖昧さを解消したりしないでください。資料の開示と票のlockは担当者の手順に従います。

## 迷いやすい4つの違い

| label | 平易な意味 |
| --- | --- |
| partial | 一部は正しいが、必要な意味の要素が足りない。明確な矛盾はない。 |
| distorted | 対象の事実について書いてあるが、人・数値・関係の向き・否定など重要部分が原文と矛盾する。矛盾がある場合はpartialよりこちらを優先する。 |
| absent | 読める対象資料の中に、その事実の意味内容が見当たらない。引用番号だけでは事実が書かれたことにならない。 |
| unclear | 資料はあるが、複数の読み方が残り、どのlabelか確定できない。 |

分からないときは無理に決めずunclearにし、迷った箇所・読み方・理由を残してください。資料自体がない／読めない場合はmissingとして報告し、unclearやabsentと混ぜないでください。各段階のlabel名は異なるため、該当するCodebookの欄を使います。最終短答に途中の橋渡し事実が書かれていないだけでは失敗としません。

## 独立して判定する

初回判定中は相手Reviewerと相談せず、相手のlabelも見ず、自分の票を作ってlockしてください。2名の票を保存した後にだけ、担当者の手順で不一致を話し合います。相談後の結果は別記録にし、最初の票は上書きしません。

ここでの「独立」は**判定手順が独立している**という意味です。著者の家族・指導教員・友人などかどうかは別の事項です。著者との関係、研究への関与、既に見たcaseは開始前に担当者へ伝えてください。関係があることを隠したり、「関係なし」に置き換えたりしません。

Pilot中に`unclear`が頻発する、Codebookの同じ箇所で繰り返し迷う、重要な境界で安定して判断できない、新しい規則を繰り返し追加する必要が出る場合は、Main Reviewへ進まず担当者へ伝えてください。Codebookや練習資料の見直しが必要です。高い一致率を作ることより、基準を実際に使えるかを確かめるのがPilotの目的です。
